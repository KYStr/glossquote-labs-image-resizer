## Confirmed defect and minimal change

The external report was reviewed as evidence, including its proposed patch, eight regression inputs and oracle. Its scripts were not executed. Independently added tests reproduced the current implementation's error: 22×11, width 15 produced 15×7 instead of 15×8. The intermediate `11 * (15 / 22)` is below the exact 7.5 half pixel.

Only the rounding computation in `public/js/core/dimensions.mjs` changes. It uses `max(1, floor((2 * size * edge + basis) / (2 * basis)))`. Positive half pixels round up; other fractions round to the nearest integer. No epsilon, unconditional ceil, API change, new dependency or UI change is involved.

The existing input gates bound size ≤8192 and edge ≤4000. Thus the integer numerator is at most 65,544,192 and the denominator at most 16,384, both exactly representable by Number. The quotient is bounded by 8192, and a noninteger quotient is at least 1/16,384 from an integer, well beyond floating-point rounding error at that scale. The existing 8192-edge/12MP input, 4000-edge/8MP output, at-least-1px, no-enlargement, exact string validation, three modes and PNG/JPEG input restrictions remain intact.
